# Infrastructure (Terraform modules + Terragrunt)

Study setup, kept minimal. Region `us-east-1`. Roughly $0.25/hour while running.

```
terraform/
  modules/                  plain Terraform, no registry modules
    vpc/                    VPC, 2 public + 2 private subnets, internet gateway, 1 NAT gateway
    ecr/                    image repositories (scan on push, keep last 10 images)
    eks/                    cluster, node group (2 x t3.small, private subnets), OIDC provider for IRSA
    rds/                    Postgres 16 db.t4g.micro, subnet group, security group (5432 from the nodes only)
    alb-controller/         IAM role + Helm chart of the AWS Load Balancer Controller (creates the ALB)
  live/
    root.hcl                region, names, S3 state backend, AWS provider (shared by all units)
    study/<unit>/terragrunt.hcl   one unit per module, wired together with `dependency` blocks
```

Order (terragrunt works it out): vpc, ecr -> eks -> rds, alb-controller.

## CI/CD (GitHub Actions)

Everything below can run from GitHub instead of your laptop (`.github/workflows/`):

* `deploy.yml`, one pipeline in order: infrastructure, then the application. A pull request runs `plan` (read-only role)
  and the backend tests. A push to `master` runs the tests, builds and pushes all images tagged with the commit, and commits
  the tag into `kubernetes/kustomization.yaml`; Argo CD rolls it out. Infrastructure is applied only from "Run workflow"
  (Actions tab): that run applies Terraform, installs Argo CD and the `Application`, then does the app steps.

One-time setup, by hand (GitHub Actions cannot create its own login):

```bash
cd terraform/live/bootstrap/github-oidc && terragrunt apply     # OIDC provider + roles app-github-{plan,images,infra}
```

## 0. Tools

`aws` (logged in), `terraform` >= 1.10, `terragrunt`, `docker`, `kubectl`, `helm` (Terraform runs the chart, helm itself is optional).

```bash
# terragrunt (Linux amd64); check the file against SHA256SUMS on the release page if you like
curl -fsSL -o terragrunt https://github.com/gruntwork-io/terragrunt/releases/latest/download/terragrunt_linux_amd64
chmod +x terragrunt && sudo mv terragrunt /usr/local/bin/
terragrunt --version

export REGION=us-east-1
export ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
export REGISTRY=$ACCOUNT_ID.dkr.ecr.$REGION.amazonaws.com
aws sts get-caller-identity          # make sure this is the account you want
```

## 1. Create the infrastructure (about 20 minutes)

```bash
cd terraform/live/study
terragrunt run --all plan            # read it first
terragrunt run --all apply           # asks once for confirmation; creates the state bucket on first run
```

Or one unit at a time, in order: `cd vpc && terragrunt apply`, then `ecr`, `eks`, `rds`, `alb-controller`.

## 2. Connect kubectl

```bash
aws eks update-kubeconfig --region $REGION --name app-study
kubectl get nodes                    # 2 nodes Ready
kubectl get pods -n kube-system      # aws-load-balancer-controller Running
```

## 3. Build and push the images

```bash
cd ../../..                          # back to the repo root
aws ecr get-login-password --region $REGION | docker login --username AWS --password-stdin $REGISTRY
for s in backend1 backend2 backend3 backend4 frontend; do
  docker build -t $REGISTRY/app/$s:v1 ./$s
  docker push $REGISTRY/app/$s:v1
done
```

## 4. Deploy the app

`scripts/up.sh` does all of this. By hand: follow `kubernetes/README.md`.

## Destroy everything (stops the cost)

The ALB is created by the controller, not by Terraform, so delete the Ingress first or the VPC
cannot be removed.

```bash
kubectl delete -k kubernetes/ && kubectl delete secret database -n app
sleep 60                                         # let the controller delete the ALB
cd terraform/live/study
terragrunt run --all destroy
```

The state bucket `app-tfstate-<account>-us-east-1` is not destroyed; delete it by hand
(empty it, including old versions, then `aws s3 rb`) if you want it gone.

## Notes

* RDS password is generated by Terraform and stored (sensitive) in the state. Fine for study; for real
  use set `manage_master_user_password = true` on the instance.
* The Kubernetes API endpoint is open to `0.0.0.0/0` (see `live/study/eks/terragrunt.hcl`); put your IP/32 there to restrict it.
* One NAT gateway, single-AZ database, `t3.small` nodes: cheap, not highly available.
